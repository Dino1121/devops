## DevOps란?

DevOps는 **Development(개발) + Operations(운영)**의 합성어이다.

개발팀과 운영팀은 서로 다른 목표를 가진다.

- Dev: 새로운 기능, 빠른 변경, 새로운 버전 배포
- Ops: 안정적인 서비스, 변경 최소화, 장애 방지

DevOps는 이 두 영역 사이의 벽을 낮추고  
개발부터 운영까지의 전체 과정을 **협업과 자동화로 연결하는 문화이자 방법론**이다.

> 내가 만든 프로그램을 실제 서비스까지  
> 어떻게 안전하고 빠르게 전달할 것인가?

### DevOps Lifecycle

`Plan → Code → Build → Test → Release → Deploy → Operate → Monitor → Plan`

개발, 배포, 운영, 모니터링의 과정을 반복하며 지속적으로 개선한다.

## DevSecOps

DevSecOps는 DevOps 과정에 **Security(보안)**를 포함한 방식이다.

기존처럼 배포 직전에 보안을 검사하는 것이 아니라  
개발 단계부터 보안 검사를 함께 수행한다.

### 주요 검사

- 라이브러리 취약점 검사
- 비밀번호 / API Key 포함 여부 확인
- 컨테이너 이미지 취약점 검사
- 테스트 통과 여부 확인

문제가 없다면 배포까지 자동화할 수 있다.

## MLOps

MLOps는 **Machine Learning + Operations**이다.

일반 프로그램은 주로 Code를 관리하지만  
머신러닝 시스템에서는 다음 세 가지를 함께 관리해야 한다.

- Data
- Code
- Model

### MLOps Lifecycle

`데이터 수집 → 학습 → 평가 → 모델 배포 → 모니터링 → 재학습`

프로그램이 정상적으로 실행되더라도  
데이터 특성이 변하면 모델 성능이 떨어질 수 있기 때문에  
모델 성능까지 지속적으로 모니터링해야 한다.

## Handoff와 전체 과정 최적화

DevOps에서는 각자의 작업 속도뿐 아니라  
작업을 다음 단계로 전달하는 **Handoff(인계)** 과정이 중요하다.

아무리 각 단계가 빠르더라도  
중간 전달 과정에서 문제가 발생하면 전체 과정은 느려질 수 있다.

따라서 DevOps의 핵심은

> 개별 단계의 최적화가 아니라  
> **전체 과정의 최적화**

라고 볼 수 있다.

## AI 시대의 개발자

AI는 개발자를 완전히 대체하는 도구라기보다  
개발자의 능력을 확장하는 협업 도구로 활용할 수 있다.

AI 활용 과정에서 중요한 것은 다음과 같다.

`질문하기 → 생성하기 → 검증하기 → 수정하기 → 책임지기`

결과를 그대로 사용하는 것이 아니라  
개발자가 직접 이해하고 검증하는 과정이 중요하다.
